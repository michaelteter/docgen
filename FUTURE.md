# FUTURE ROADMAP AND CODE IMPROVEMENTS

This document summarizes known weaknesses and suggested improvements for the docgen project based on the current implementation.

## Code Review

The source code was almost entirely generated by LLMs (Claude 4.5 and MS Copilot GPT4). It deserves a good review by someone with good Golang experience.

⸻

⚠️ Current Weaknesses

Error Handling

- Several operations ignore or suppress errors (cmd.Output(), os.WriteFile(), etc.).
- Limited contextual logging; no consistent error reporting strategy.
- Some functions may silently skip files when errors occur (e.g., in WalkDir).

Pattern Matching

- matchesGitignorePattern() only partially implements full .gitignore semantics.
- Does not handle recursive glob patterns like \*_/foo/_.bar.
- Pattern resolution currently assumes simple filename-based matches.

Hard-Coded Constants

- maxSizeBytes (2MB) and 8KB binary read chunk are fixed.
- These values should ideally be user-configurable via flags.

I/O and Performance

- d.Info() is called inside WalkDir, which triggers an additional system call per file.
- No parallelization or concurrency; acceptable for small repos, but could be optimized.

Output Formatting

- Header padding (e.g., strings.Repeat(">", 80 - len(f) - 24)) can misalign with long filenames.
- Output might wrap or appear uneven for deeply nested files.

CLI/UX

- No verbosity or debug flag for insight into why certain files are skipped.
- Limited feedback on excluded vs. included files.

Structure & Maintainability

- All logic resides in a single docgen.go file.
- No modular separation (e.g., internal/config, internal/filter, internal/output).
- Harder to test or extend over time.

Testing

- Currently untested; need unit tests for core components:
- isBinaryFile()
- matchesGitignorePattern()
- filterIncluded()
- Tree rendering (treeString and renderTree)
- Ensure that path building/handling is correct and cross-platform.

⸻

🧩 Suggested Improvements

1. Error Handling & Logging

   - Use log.Printf() or fmt.Fprintf(os.Stderr, ...) for all non-fatal errors.
   - Return early on unrecoverable conditions.
   - Add an optional --verbose flag to print skipped files and reasons.

2. Configuration & Flags

   - Add CLI flags for:
   - --max-size (custom file size limit)
   - --read-chunk (binary detection chunk size)
   - --verbose

3. Pattern Matching

   - Replace or supplement custom matcher with a library like go-gitignore.
   - Support recursive globs (\*\*/pattern) and anchored paths.

4. Code Structure

   - Refactor into a multi-package layout to improve maintainability and test isolation.

   ```
   cmd/docgen/main.go
   internal/config/config.go
   internal/filter/filter.go
   internal/output/output.go
   ```

5. Testing Strategy

   - Add \*\_test.go files using Go’s testing package.
   - Include sample repo fixtures for reproducible behavior tests.
   - Validate exclusion logic and file tree correctness.

6. Output Enhancements

   - Replace manual padding logic with formatted templates.
   - Optionally add syntax highlighting or file type summaries.
   - Add summary statistics at the end of output (files processed, skipped, total size).

7. Performance Improvements

   - Consider buffered directory traversal with worker goroutines.
   - Cache .gitignore and .docgen_ignore pattern evaluations.

8. Documentation

   - Expand README with examples of .docgen_ignore usage.
   - Add section on known limitations and performance expectations.

⸻

✅ Future Goal

Refine docgen into a production-grade CLI utility with modular architecture, reliable error handling, and robust tests — ready for open-source adoption.
